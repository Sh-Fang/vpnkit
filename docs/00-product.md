# 00 · 产品定义

## 1. 一句话

`vpnkit` 是一个命令行工具：登入企业内网网关后，**只把内网流量送进隧道**，公网流量照走本地网络。

## 2. 要解决的问题

现成的企业 VPN 客户端有三个问题：

| 问题 | 表现 | 根因 |
|---|---|---|
| 占用默认路由 | 一连接，整机上网都慢了，下载尤其明显 | 客户端接管 `0.0.0.0/0`，公网流量也绕行隧道 |
| DNS 全量转发 | 每个新域名多一次隧道往返，首屏明显卡 | 系统 DNS 被整体指向隧道内解析器 |
| 认证状态易失 | 隔一段时间又要重新认证 / 重新登记设备 | 设备标识由硬件实时算出，硬件一变动就被当成新设备 |

`vpnkit` 的定位就是把这三点反过来做。

## 3. 用户故事

```
作为使用者
我希望 vpnkit up 之后，我访问内网系统正常，同时看视频、下载大文件速度不变
这样我就不需要「连 VPN 时忍着用，不连时干不了活」
```

```
作为使用者
我希望 down 之后我的路由表和 DNS 恢复到连之前一模一样
这样我不用担心工具残留状态把网络搞坏
```

```
作为使用者
我希望设备标识保持稳定，不要每隔几天就被要求重新登记
这样我不用反复找管理员审批
```

## 4. CLI 规格

### 4.1 命令

| 命令 | 作用 | 需要提权 |
|---|---|---|
| `vpnkit login --server <host> --user <name>` | 认证并保存会话令牌 | 否 |
| `vpnkit logout` | 清除本地令牌 | 否 |
| `vpnkit up [--dry-run] [--verbose]` | 建立隧道、安装分流 | 是 |
| `vpnkit down` | 拆除隧道、恢复网络 | 是 |
| `vpnkit status [--json]` | 打印状态与统计 | 否 |
| `vpnkit doctor` | 环境自检（权限、TUN 设备、路由工具） | 否 |
| `vpnkit devid show` / `devid pin <value>` | 查看/固化设备标识 | 否 |

### 4.2 全局参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--config` | `~/.config/vpnkit/config.toml` | 配置文件路径 |
| `--verbose` | false | 调试日志 |
| `--json` | false | 机器可读输出（`status`/`doctor`） |
| `--timeout` | `30s` | 单次网络操作超时 |

### 4.3 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 通用失败 |
| 2 | 参数错误 |
| 3 | 认证失败 |
| 4 | 隧道建立失败 |
| 5 | 权限不足 |
| 6 | 网络配置失败（路由/DNS） |
| 7 | 服务端拒绝（被踢、会话冲突等） |

## 5. 验收标准

以下每条都必须可测量、可复现。

### P1 认证

- [ ] `login` 成功后 `~/.config/vpnkit/session.json` 存在且权限 `0600`
- [ ] 令牌过期时 `up` 返回退出码 3 并提示重新 `login`，不 panic
- [ ] 密码不出现在任何日志、进程参数、配置文件中

### P2 隧道

- [ ] `up` 在 10 秒内完成握手并进入 `RUNNING`
- [ ] `--verbose` 能看到握手五个阶段的字节数：82 / 122 / 43 / 76 / 40
- [ ] 握手失败时给出可区分的错误（拒绝 / 超时 / 格式不符）

### P3 分流

- [ ] `up` 后 `netstat -rn`（或等价）里**默认路由指向原网关**，未被修改
- [ ] 只有服务端下发的内网网段指向 TUN 设备
- [ ] `ping` 内网主机通，`ping 8.8.8.8` 仍走物理网卡（`traceroute` 首跳不变）
- [ ] `up` 期间公网下载速度与 `down` 状态差异 < 10%
- [ ] `down` 后路由表与 `up` 前逐行一致
- [ ] 进程被 `SIGKILL` 后，下次 `up` 能检测并清理残留路由

### P4 DNS

- [ ] 内网域名解析走隧道 DNS，公网域名走系统原解析器
- [ ] `down` 后 DNS 配置完全恢复
- [ ] 断网重连后分区解析自动恢复，无需重新 `up`

### P5 稳定性

- [ ] 连续运行 8 小时无内存增长（RSS 波动 < 20%）
- [ ] 服务端踢下线后 3 秒内状态变为 `STOPPED` 并打印原因
- [ ] 网络切换（Wi-Fi ↔ 有线）后 30 秒内自动重连或明确报错

## 6. 非目标

明确**不做**的事，避免范围蔓延：

- 不做图形界面
- 不做系统代理（SOCKS/HTTP proxy）模式——只做 TUN 分流
- 不做多用户/多配置并存
- 不做流量统计上报
- 不实现应用级（按进程）分流——那是另一个量级的工作，见 `docs/12` 的将来项
- 不追求比现有客户端更强的加密——加密原语是兼容性约束，见 `docs/05`

## 7. 术语

| 术语 | 含义 |
|---|---|
| 网关 | 提供认证与隧道接入的服务端 |
| 会话令牌 | 认证后拿到的票据，后续请求带在头部 |
| 控制通道 | 承载命令的隧道连接 |
| 数据通道 | 承载裸 IPv4 包的隧道连接 |
| 分流 | 只把特定网段/域名的流量送进隧道 |
| 设备标识 | 用于设备绑定的稳定字符串，见 `docs/06` |
